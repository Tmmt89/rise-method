# Rise Method

Один пакет для Codex (`$rise-method`) и Claude Code (`/rise-method`). Инструкции и база общие; для вспомогательных команд нужен Python 3.10+. `agents/openai.yaml` — необязательные метаданные интерфейса Codex; выполнение методики от них не зависит.

Создавай запрошенный материал с исполнимыми заданиями, проверенными ответами и наблюдаемыми критериями. Масштаб результата следует запросу: упражнение, урок, курс, адаптация или аудит. Skill уже пригоден для авторской работы; методика версии 0.1.0 ещё требует реальных пилотов.

## Подключить основания

Выполни `python3 "<skill-dir>/scripts/query.py" status`, где `<skill-dir>` — фактическая папка загруженного SKILL.md, независимо от клиента. На Windows допустимо `py -3` вместо `python3`. Скрипт только читает данные. Публичный пакет содержит методическую базу в `references/basis`; он работает без исходной папки автора. При необходимости подключи другую базу через `--workspace`, `RISE_METHOD_WORKSPACE` или [references/workspace.json](references/workspace.json). Явно заданный недоступный путь является ошибкой, а не разрешением молча сменить основания.

Используй [references/catalog-access.md](references/catalog-access.md), чтобы выбирать записи по ID и читать источник спорного решения. Загружай основной профиль и реально используемые методы/активности, а не все каталоги. Встроенная база — версионированный снимок авторского методического синтеза; оригинальные учебники, записи и исходный код платформы в него не входят. Подключённая локальная база читается в текущей версии.

## Выполнить запрос

1. **Определить режим и brief.** Используй сведения из запроса, курса и доступных материалов. Зафиксируй цель, аудиторию, известные предпосылки, время, формат и ограничения; отличай неизвестное от факта. Существенный вопрос задавай только если ответ меняет зависимую работу, продолжая независимую часть. Полный паспорт — `text blueprint`; определения — `text glossary`, когда термин неоднозначен.
2. **Выбрать результат и маршрут.** Для курса сначала свяжи результаты модулей, предпосылки, возврат к языку и checkpoints. Для урока назначь основной профиль, критерии ученика и framework по доступному знанию. Прочитай выбранные PR/CTX и `selector frameworks`, затем полный выбранный FW. Укажи `framework_use_as`; guided discovery — встроенный метод, а Teach в TTT зависит от диагностической попытки.
3. **Создать или переработать материал.** Выбери ACT через `selector activities` и прочитай полные контракты выбранных семейств. Заполни действительные стимулы, инструкции, роли, действия слушателя/читателя, помощь, ответы/рубрики, feedback и полный бюджет времени. Семейство задания или список названий этапов не является готовым уроком. При адаптации сохраняй целевую операцию либо явно меняй результат и критерий.
4. **Проверить способ исполнения.** Для материала RiseAcademy прочитай `bindings ACT-...` и указанные PLAT. Проверь актуальность основания через `platform-check PLAT-...`; при изменившемся коде перечитай затронутую реализацию. Без подключённого репозитория используй карту как датированное основание, сохраняя проверку текущей платформы незавершённой. Неподтверждённую функцию замени проверенным ручным процессом или подходящей задачей. При подготовке настоящего цифрового пакета прочитай `text platform` и текущий контракт формата; методический JSON не является API импорта.
5. **Проверить и исправить результат.** Получи `checks --gate authoring`, выбери применимость каждого QC к запрошенному масштабу, прочитай его полное требование через `get`. Независимо реши закрытые задания; для открытых примени критерии, проверь модели/медиа, время обоих участников и видимость. Исправь найденное, повтори зависимые проверки. QA материала и оценка ученика — разные рубрики.
6. **Передать конкретный результат.** Сохрани запрошенные артефакты в рабочем проекте или указанной пользователем папке; при отсутствии выбора используй `materials/<понятное-имя>/`. Дай ссылки, существенные решения, границы проверки и следующую зависимость. Не завершай работу лишь предложением создать пакет, который уже заказан.

Режимы с разными выходами и критериями завершения: [references/deliverables.md](references/deliverables.md). Для аудита начинай с реального артефакта; выбирай исправления по его цели, а не заменяй всё новым уроком. Для небольшого упражнения используй нужную часть контракта, без навязывания полного курса.

## Сохранить смысл и достоверность

- Свяжи **результат → действие → наблюдаемое свидетельство → критерий → помощь**. Узнавание, самостоятельное использование, completion платформы и уровень языка — разные выводы.
- Языковое объяснение и ключ опираются на проверенный контекст. Noticing требует реального фрагмента модели; полезные фразы вне неё — extension. Авторские/адаптированные материалы имеют соответствующий provenance.
- Выбирай условия из профиля и активности: receptive/productive, intensive/extensive, индивидуальное письмо/peer review. Учительский пример, локальный TP и явный совет источника сохраняют разную доказательность. Для спора прочитай карточку через `source`, затем `text decisions`, если нужно разрешение расхождения.
- Применяй школьные нормы в установленной области, с учётом явных указаний пользователя. Уже данное указание изменить требование фиксируй как изменение, без повторного запроса разрешения.
- Точные современные экзаменационные правила/шкалы и внешние факты проверяй по текущему первичному источнику, если они нужны результату. При отсутствии такой проверки возможна честно обозначенная formative IELTS-style практика, без придуманных band/CEFR или ошибок будущих учеников.
- Runtime, фактический пилот, реальные ответы и эффект обучения отмечай только после соответствующего наблюдения. `status` и скрипты проверки структуры сами этого не подтверждают.

## Когда работа завершена

Выдан весь заказанный объём, ключи/критерии и необходимые ресурсы существуют, применимые проверки имеют свидетельства, существенные исправления внесены. В QA используй `pass / fail / unknown / not_applicable`; у N/A есть причина. Готовность записывай по контракту: `authoring_draft`, `ready_for_rehearsal`, `ready_for_pilot`, `pilot_reviewed`. Ограничение конкретной зависимости не мешает завершить независимые части пакета. Название установленного skill не означает, что педагогические пилоты уже проведены.

При разрешённой технической репетиции выполняй применимые runtime QC. Если заказан только аудит/план/Markdown-пакет, не расширяй работу до публикации или изменений Speaking_livekit. Подготовка материала не создаёт самостоятельного разрешения на отправку учащимся, импорт в рабочую БД или публикацию.
